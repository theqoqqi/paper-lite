# [RFC 002] 2D-генерация этажа подземелья и камера 5x5

## 1. Резюме решений

* **Проблема:** Линейная прогрессия (10 комнат подряд) лишена тактической глубины, исследования и вариативности маршрутов.
* **Решение:**
  * Процедурная генерация ветвящегося подземелья на координатной 2D-сетке.
  * Стартовая комната на `(0, 0)` является тупиком, от которого формируется дерево комнат с развилками.
  * Количество комнат на этаже масштабируется: `10 + floor * 2` (Этаж 1: 10, Этаж 2: 12, Этаж 3: 14, Этаж 4: 16).
  * Босс этажа всегда размещается в самом удаленном тупике (максимальная длина пути от старта по графу).
  * Камера 5x5 с центрированием на игроке: ячейка персонажа всегда находится в центре видоискателя.
  * Туман войны: скрывает неизведанные комнаты, но автоматически раскрывает тип и иконку соседних комнат, соединенных дверным проемом.
  * Управление перемещением: прямой клик по смежным комнатам, соединенным открытой дверью.
  * Свободный бэктрекинг: ранее зачищенные комнаты безопасны для прохода, бонусы костров и событий строго одноразовые.

---

## 2. Контракты и структуры данных

### Модель комнаты подземелья

```javascript
// Хранилище в Game: this.dungeonRooms = { "x,y": RoomObj }
{
    id: "0,0",
    x: 0,
    y: 0,
    type: "start", // "start" | "battle" | "elite" | "event" | "shop" | "campfire" | "boss"
    doors: {
        up: false,
        down: false,
        left: false,
        right: false,
    },
    explored: true, // Игрок заходил в комнату
    cleared: true,  // Контент комнаты разрешен (бой выигран, костер использован)
    visible: true,  // Разведана туманом войны (видна на карте)
}
```

### Позиция игрока на карте

```javascript
this.playerPos = { x: 0, y: 0 };
```

### Вьюпорт 5x5

* Диапазон видимости рассчитывается от позиции игрока `(px, py)`:
  * `x` от `px - 2` до `px + 2`.
  * `y` от `py - 2` до `py + 2`.
* Центр `[2, 2]` — текущая комната игрока с маркером героя.

## 3. Обработка краевых случаев и отказов

* **Пустые ячейки:** координаты внутри вьюпорта 5x5, где нет сгенерированной комнаты, отображаются как темные пустые блоки без дверей и реакций на клик.
* **Случайные соседи:** если ветви генерации случайно соприкоснулись, проход между ними создается с вероятностью 15%, в 85% случаев остается глухая стена.
* **Изоляция боев:** тактическое бегство запрещено. Вход в неисследованную комнату с боем запускает сражение до победы или гибели.
* **Одноразовость бонусов:**
  * `campfire`: после первого отдыха костер помечается `cleared: true`. Повторный вход сообщает: «Угли костра остыли».
  * `event`: разрешается единожды, повторный вход — пустая комната.
  * `shop`: купленные позиции сохраняют статус `bought: true`, доступные товары можно докупать при повторном визите.
* **Сериализация:** `dungeonRooms`, `playerPos` и `floor` сохраняются в `serializeState()` и восстанавливаются в `loadGame()`.

## 5. Стратегия ручной верификации

1. **Проверка генерации и центрирования:**
   * Начать забег, убедиться, что игрок в центре сетки 5x5 на стартовой комнате.
   * Проверить, что смежные за дверями комнаты отображают свои типы, а остальные скрыты.
2. **Проверка перемещения:**
   * Кликнуть по доступной соседней комнате — убедиться, что игрок переместился, сетка 5x5 сдвинулась, а камера осталась на игроке.
   * Кликнуть по стене или недоступной клетке — убедиться в отсутствии перехода.
3. **Проверка боя и возврата:**
   * Зайти в комнату боя, победить врагов.
   * Вернуться назад на старт и снова войти в комнату боя — убедиться, что повторный бой не запускается.
4. **Проверка сейва:**
   * Сохранить игру посреди исследованного лабиринта, перезагрузить страницу, проверить совпадение карты, позиции и тумана войны.
