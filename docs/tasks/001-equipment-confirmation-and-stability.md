# [RFC 001] Подтверждение экипировки и стабилизация состояния

## 1. Резюме решений

* **Проблема:**
  * При получении оружия или брони в бою (элита/босс) или из событий (сундук) предмет экипируется автоматически, уничтожая текущий билд игрока без возможности отказаться или сравнить статы.
  * На экране карты возможен фатальный сбой `TypeError: Cannot read properties of undefined (reading 'type')`, если объект комнаты не найден.
  * При загрузке сохранения через `loadGame` игрок создается с жестко зашитым классом `"wanderer"`, что стирает специфичные параметры других классов.
  * Во время пошагового хода врагов игрок может переключать фокус цели, сбивая визуальное отображение боя.
* **Границы задачи (Scope):**
  * **Входит:**
    * Интеграция экрана подтверждения экипировки (надеть со сдачей старого за 25% стоимости vs разобрать новый на 25% золота).
    * Поддержка наград экипировки как в завершении боя, так и в текстовых событиях.
    * Сериализация неразрешенного предмета (`pendingEquipment`) при сохранении игры.
    * Исправление краша на карте (`curRoomObj?.type`).
    * Исправление гидратации классов в `loadGame`.
    * Блокировка переключения таргета при `isProcessingTurn === true`.
  * **Исключено (Non-goals):**
    * PWA, Service Worker и manifest (зафиксированы в `docs/improvement-ideas.md`).
    * Генерация развилок на карте (зафиксирована в `docs/improvement-ideas.md`).
    * Инвентарь запасной экипировки (рюкзак).

## 2. Контракты и структуры данных

### Поле неразрешенной экипировки в `Game`

```javascript
// src/game-engine.js
this.pendingEquipment = null; 
// Формат: { item: Object, origin: "battle" | "event" }
```

### Формула компенсации золота

```javascript
function calculateSalvageGold(item) {
    if (!item || !item.cost || item.cost <= 0) return 0;
    return Math.max(1, Math.floor(item.cost * 0.25));
}
```

### Состояние экрана наград для событий

* Введение состояния `game.state = "EVENT_REWARDS"` для событий, выдающих экипировку (например, сундук), аналогично завершению боя.
* Кнопка «Продолжить» блокируется, если `this.pendingEquipment !== null`.

## 3. Обработка краевых случаев и отказов

* **Нулевая или отсутствующая цена:** если у старого предмета (кулаки, лохмотья) нет поля `cost`, продажа дает `0G`, исключая `NaN`.
* **Выход из игры на экране наград:** `pendingEquipment` сохраняется в `serializeState()` и корректно восстанавливается в `loadGame()`.
* **Поврежденные данные карты:** если `mapRooms` поврежден или номер комнаты выходит за пределы массива, `curRoomObj?.type` безопасно фоллбэчится на `"battle"`, предотвращая падение UI.
* **Смена цели во время анимации:** клик по карточке врага игнорируется при `this.isProcessingTurn === true`.

## 5. Стратегия ручной верификации

1. **Проверка экипировки в бою:**
   * Запустить игру, дойти до комнаты с элитой (#5) или победить босса (#10).
   * Убедиться, что при выпадении оружия/брони открывается блок сравнения со статами старого и нового предмета.
   * Проверить вариант «Разобрать»: золото увеличивается на 25% цены нового, старый предмет остается на месте.
   * Проверить вариант «Надеть»: новый предмет экипируется, золото увеличивается на 25% старого.
2. **Проверка событий:**
   * В событии сундука при открытии предмета убедиться в переходе на экран наград и корректной работе выбора.
3. **Проверка сейвов:**
   * Сохранить игру в Слот #1 в момент активного выбора экипировки, перезагрузить страницу и загрузить слот. Убедиться, что выбор не пропал.
4. **Проверка защиты кликов:**
   * Во время анимации ходов противников кликнуть по другому врагу — убедиться, что таргет не сменился до окончания хода.
