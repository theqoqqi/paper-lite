# [RFC] Автономный безголовый симулятор баланса предметов и перков

## 1. Резюме решений

* **Проблема:**
  * Оценка силы и баланса предметов/перков строится на субъективных ощущениях и ручных тестах, из-за чего скрытые синергии (например, связки критов у Ассасина, пассивный автопилот или бесконечный сустейн) пропускаются или выявляются случайно.
  * Требуется детерминированный инструмент, способный за секунды обсчитывать сотни тысяч реальных боёв и выявлять статистические аномалии силы предметов.

* **Согласованные решения:**
  * **Автономный раннер `scripts/simulate-balance.js`:**
    * Работает в чистом Node.js без внешних пакетов (no-npm).
    * Использует реальный игровой движок `Game`, `Player`, `BattleSystem` через синхронное мокирование таймеров (`global.setTimeout = (fn) => fn()`).
  * **Мульти-профильный ИИ и атаки игрока:**
    1. *Общие боевые стили:*
       * *Aggro AI:* максимальный темп и урон, слив EN в атакующие навыки, защита только при смертельной угрозе.
       * *Turtle/Control AI:* прожатие «Защиты» по кулдауну, затягивание боя, победа измором и дотами.
       * *Smart AI (Адаптивный):* чтение намерений врага (блок под замах `charge`, сбитие щитов Пробитием, добивание Казнью ради экстра-хода, Вихрь при 2+ целях).
    2. *Специализированные фокус-профили по типам атак (Skill-Bias Runs):*
       * *Fast Focus:* спам Быстрого удара (активирует `p7`, `p35`, `p11`, вампиризм от атак, триггеры крита).
       * *Execute Focus:* приоритет Казни при любой возможности (проверяет `p1`, `p15`, `p24`, цепочки экстра-ходов).
       * *Pierce Focus:* приоритет Пробития против щитовиков и бронированных врагов (`p8`, `p15`, `p24`, `art3`).
       * *Whirlwind Focus:* спам Вихря по кулдауну против групп (`p7`, `p24`).
       * *Defend Focus:* прожатие Защиты строго по кулдауну (`p14`, `p31`, `art18`, шипы).
       * *Concentrate Focus:* цикл через сброс кулдаунов и отхил (`p9`, `art10`).
    3. *Замер эффективности на нажатие (Value Per Cast):*
       * Трекинг урона и исцеления за каждое применение конкретного навыка (насколько перк/предмет усиливает именно профильную кнопку).
  * **Матрица сценариев:**
    * Сценарий 1: *«Ранний пак»* (Этаж 0, 2 моба).
    * Сценарий 2: *«Групповой бой»* (Этаж 2, 3 моба с мутациями).
    * Сценарий 3: *«Элита»* (Этаж 1 и 2, 1 на 1 против элитного врага).
    * Сценарий 4: *«Босс»* (Агарик / Вулкан с затяжным боем).
    * Сценарий 5: *«Истощение»* (мини-забег из 5 комнат подряд без восстановления HP).
    * Классовые срезы: Странник, Ассасин (крит-билд), Крестоносец (танк-билд).
  * **Двухуровневый запуск и фильтры:**
    * Быстрый аудит: `node scripts/simulate-balance.js` (100 боёв на тест, ~3 сек).
    * Глубокая валидация: `node scripts/simulate-balance.js --full` (500 боёв на тест, ~15 сек).
    * Таргетный фильтр: `node scripts/simulate-balance.js --id p35` или `--category artifacts`.
  * **Формат вывода:**
    * Консольная сводная таблица в терминале с цветовой подсветкой аномалий.
    * Автоматическая генерация подробного отчёта в [`docs/balance-report.md`](../balance-report.md) с метриками: `Average Impact`, `Peak Scenario`, `Worst Scenario`, `Verdict`.

## 2. Архитектура и структура симулятора

Скрипт располагается в директории `scripts/simulate-balance.js`.

### 2.1. Изоляция и окружение Node.js

```javascript
// Мокирование браузерного окружения перед импортом систем
global.localStorage = { getItem: () => null, setItem: () => {}, removeItem: () => {} };
global.window = { addEventListener: () => {}, removeEventListener: () => {} };
global.setTimeout = (fn) => { fn(); return 0; };
```

### 2.2. Профили поведения ИИ и специализированные фокусы атак

Симулятор поддерживает двухуровневую систему выбора действий:

1. **Глобальные тактические стили (General Archetypes):**
   * `smart` (Адаптивный):
     * Приоритет парирования: если у любого живого врага намерение `charge` и кулдаун `defend === 0` — использует «Защиту».
     * Приоритет казни: если врага можно гарантированно добить «Казнью» (`hp <= dmg`) и кулдаун готов — бьёт «Казнью» для получения экстра-хода.
     * Приоритет разрушения брони/щита: если у цели высокий щит/DEF — бьёт «Пробитием».
     * Приоритет АОЕ: если живых врагов 2 или больше и вихрь готов — кастует «Круговой вихрь».
     * Иначе: ротация «Быстрый удар» / «Тяжёлый удар» по балансу энергии.
   * `aggro` (Берсерк):
     * Максимизация DPS в один таргет, полный игнорирование блока, слив энергии в самые мощные доступные атаки.
   * `turtle` (Черепаха):
     * Постоянный спам «Защиты» и «Концентрации», затягивание боя для проверки сустейна и пассивных дотов.

2. **Специализированные фокус-профили атак (Skill-Bias Runs):**
   При запуске тестов на синергию конкретных навыков включаются принудительные веса:
   * `fast_focus`: абсолютный приоритет «Быстрого удара» (тест триггеров он-хита, критов, яда, возврата энергии).
   * `execute_focus`: агрессивный упор на «Казнь» при малейшей возможности добивания.
   * `pierce_focus`: приоритет «Пробития» против любых бронированных целей и мобов со щитами.
   * `whirlwind_focus`: спам «Кругового вихря» по кулдауну.
   * `defend_focus`: спам «Защиты» и генерации щита по кулдауну.
   * `concentrate_focus`: цикл перезарядки навыков через «Концентрацию».

```javascript
function decideAction(game, profile) {
    const p = game.player;
    // Smart: реакция на замах врага
    if (profile === "smart" && hasIncomingCharge(game) && p.cooldowns.defend === 0) {
        return "defend";
    }
    // Фокус-профили: проверка доступности приоритетного навыка
    if (profile === "fast_focus" && p.energy >= 1) return "fast";
    if (profile === "execute_focus" && p.cooldowns.heavy === 0 && p.energy >= 2) return "heavy";
    if (profile === "pierce_focus" && p.cooldowns.pierce === 0 && p.energy >= 2) return "pierce";
    if (profile === "whirlwind_focus" && p.cooldowns.whirlwind === 0 && p.energy >= 3) return "whirlwind";
    if (profile === "defend_focus" && p.cooldowns.defend === 0 && p.energy >= 1) return "defend";
    if (profile === "concentrate_focus" && p.cooldowns.concentrate === 0) return "concentrate";
    ...
}
```

### 2.3. Сбор и агрегация метрик

Для каждого тестируемого предмета собираются два блока данных:

#### 1. Общие показатели боевой эффективности (Global Impact)

* `avgDamage`: суммарный чистый урон, нанесённый персонажем врагам за срез комнат.
* `deltaDamage`: $\Delta\text{Damage} = \max(0, \text{Damage}_{\text{item}} - \text{Damage}_{\text{base}})$.
* `deltaDamagePct`: относительный прирост урона забега в процентах.
* `avgRooms` и `deltaRooms`: количество полностью зачищенных комнат среза (из 4.0) и дельта к базовой линии.
* `roi`: показатель экономической отдачи $\text{ROI} = \Delta\text{Damage} / \text{Cost}$ (урон на 1 золотой).
* **Синхронизация окружения (Room-Seeding):** детерминированный генератор псевдослучайных чисел `mulberry32` гарантирует, что каждая комната среза инициализируется идентичным сидом для базового персонажа и для каждого предмета. Это полностью исключает случайный статистический шум спавна врагов и появление отрицательных чисел.
* **Категория экономики (`NON_COMBAT_IDS`):** небоевые предметы (на золото, опыт, костры) получают вердикт `💰 Экономика / Вне боя` с нулевыми дельтами боевого урона.

#### 2. Метрики отдачи на способность (Value Per Cast & Skill Synergy)

Внутри цикла боя перехватываются и логгируются результаты каждого нажатия кнопки игрока:

* `castsCount[skill]`: общее количество применений каждого навыка (`fast`, `heavy`, `pierce`, `whirlwind`, `defend`, `concentrate`).
* `damagePerCast[skill]` ($\text{DPC}$): суммарный нанесённый прямой и дот-урон, разделенный на количество кастов этого навыка.
* `effectiveDefensePerCast[skill]` ($\text{EDPC}$): среднее количество поглощённого щитом/защитой урона или полученного отхила за 1 каст (для «Защиты» и защитных перков).
* `skillSynergyDelta` ($\Delta\text{DPC} = \text{DPC}_{\text{item}} - \text{DPC}_{\text{base}}$): чистый прирост эффективности навыка от предмета. Позволяет сразу увидеть: «Перк X усиливает Быстрый удар на +85%, превращая спам-кнопку в убийцу баланса».

## 3. Обработка краевых случаев и отказов

* **Защита от бесконечного цикла:** лимит раундов боя `MAX_TURNS = 35`. Если бой не завершился за 35 раундов (например, бесконечный блок слизня и игрока), фиксируется технический тайм-аут (поражение), предотвращая зависание раннера.
* **Изоляция сбоев:** каждый тестовый запуск обёрнут в `try/catch`. Если конкретный предмет вызывает рантайм-ошибку, скрипт не падает, а помечает предмет как `ERROR: <сообщение>` в отчёте.
* **Нулевой базовый винрейт:** при вычислении дельт деление на ноль экранируется безопасными проверками.
